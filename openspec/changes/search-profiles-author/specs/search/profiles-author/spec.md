# Spec Delta

## Purpose

搜索方案保存可复用的跨来源检索组合；创作者平台名称保存用户已知的来源名称，点击后执行该来源普通搜索。2026-11-02 owner 批准用此设计替换原作者专用聚合查询及 B2 详情按钮。

## ADDED Requirements

### Requirement: 搜索方案持久化

系统 MUST 支持命名搜索方案，方案至少包含来源顺序、启用状态和各来源搜索选项。名称 MUST trim 后非空、≤30 字符且同库不重名；缺省无方案时 MUST 保持现有全局来源搜索行为。

#### Scenario: 保存检索方案

- **WHEN** 用户保存「补全作品」方案，启用来源 A、B 并为 B 设置非默认选项
- **THEN** 方案保留来源顺序、启用状态和 B 的选项，未选择方案时现有全局搜索行为不变

### Requirement: 方案 CRUD 与恢复

用户 MUST 能新建、重命名、更新、删除和选择方案。读取方案时 MUST 按当前来源 option schema 校验值，未知来源或无效值 MUST 忽略或回退默认值，不得阻塞其他来源搜索。

#### Scenario: 来源选项变更

- **WHEN** 来源 B 删除了方案中已保存的某个选项值
- **THEN** 加载方案时 B 回退该选项默认值，来源 A 仍按方案值执行

### Requirement: 聚合结果一致性

按方案启动聚合搜索时，系统 MUST 按保存顺序加载启用来源，并将该来源的有效选项传递给分页结果页；后续分页 MUST 使用同一组选项，不能退回来源默认值。

#### Scenario: 聚合分页

- **WHEN** 用户选择方案并加载来源 B 的下一页
- **THEN** 下一页沿用方案为 B 解析出的有效选项，而不是重新读取 B 的默认选项

### Requirement: 创作者平台名称树

收藏「创作者」区域 MUST 在恰好选中一个创作者时于列表下方显示其平台名称，按具体 source key 分组，支持一个来源多个名称；零选/多选 MUST 隐藏树。平台标题 MUST 只展开/折叠，名称行 MUST 可用键盘激活搜索。现有收藏作者/标签/阅读筛选及导航返回状态 MUST 保留。窄屏筛选界面 MUST 根据其当前本地作者选择提供同等功能。

#### Scenario: 单选创作者

- **WHEN** 用户选中「おせんべいの森 (だにまる)」且它已关联 Picacg 下两个名字、禁漫天堂下一个名字
- **THEN** 该作者下出现两个平台分组及三个名称；选中、展示与展开分组均不触发网络搜索；改为多选后树隐藏

#### Scenario: 窄屏与键盘

- **WHEN** 用户在窄屏筛选界面将本地作者选择改为一个，并使用 Tab 和 Enter/Space 激活名称
- **THEN** 显示对应平台树并执行相应名称搜索，长名称可查看全文，布局不溢出，标签区与原筛选操作仍可用

### Requirement: 已知原名与手动维护

系统 MUST 从全部本地收藏的已知原始作者及现有人工 alias 关系收集名称，MUST NOT 受当前文件夹、系列、搜索或其他筛选截断，也不得猜测新别名。用户 MUST 能添加、编辑、删除平台名称，非空校验及同创作者同 source key 同名称去重 MUST 生效；不同名称 MUST 允许共存。映射及对自动名称的隐藏记录 MUST 持久化，删除 MUST NOT 删除收藏或修改其原始元数据。

#### Scenario: 平台多名称与刷新

- **WHEN** 用户为 Picacg 添加「だにまるstudio」，修正或删除一个自动收集名称，然后刷新或重启
- **THEN** 手动名称仍在，旧被修正/删除的名称不复活，其他平台及收藏数据不变；当前文件夹以外的已关联名称仍可显示

### Requirement: 作者归并与写入归属

手动名称 MUST 按原始作者 anchor 关联现有 alias 分组，作者合并/重命名后 MUST 保留名称；撤销 alias 后 MUST 跟随原 anchor 且不得复制或丢失。写入 MUST 使用现有持久化事务并保护页面、数据库连接及数据目录归属；异步编辑不得写到后来选中的其他作者，失败 MUST 保留旧有效状态并反馈。

#### Scenario: 合并与撤销

- **WHEN** 作者甲的手动平台名称随既有作者合并操作归入作者乙，之后撤销该 alias
- **THEN** 名称先显示于乙，撤销后回到甲所属分组，记录不被删除或重复分发

#### Scenario: 编辑期间切换

- **WHEN** 用户编辑甲的名称时切换创作者或数据目录，旧编辑随后完成
- **THEN** 操作被取消或只在仍有效的原归属下完成，不覆盖新创作者/新数据目录的数据；持久化失败不显示成功

### Requirement: 来源普通搜索等价

点击平台名称 MUST 打开所绑定来源的普通搜索结果页，使用该名称本身作关键词及该来源正常默认搜索选项，分页 MUST 延续同一关键词和选项。MUST NOT 拼接作者语法、调用作者专用转换/标签跳转、套用聚合方案或请求其他来源。同显示名来源 MUST 按具体 key 区分。已保存来源卸载/不支持普通搜索时 MUST 保留记录、明确不可用并禁止请求或错误回退。

#### Scenario: 按平台名称搜索

- **WHEN** 用户点击 Picacg 分组下的「だにまるstudio」
- **THEN** 只打开绑定 Picacg 来源的普通搜索，关键词恰为「だにまるstudio」，选项等同该来源正常默认值；后续分页参数保持一致

#### Scenario: 来源不可用

- **WHEN** 已保存名称所绑定的来源被卸载，或另一来源恰好使用相同平台显示名
- **THEN** 原记录显示不可用并禁止请求，不跳到同名来源；相同 source key 恢复后可重新使用

### Requirement: 废止旧作者聚合入口

系统 MUST 移除本 change 新增的详情「跨平台搜索」按钮、作者聚合 fallback、专用 author intent/转换/聚合分支及仅服务它们的测试/翻译。F6 方案及既有单源作者标签、作者快捷方式、搜索历史行为 MUST 保留；新面板不得要求来源实现 `search.author`。

#### Scenario: 旧入口替换

- **WHEN** 用户打开漫画详情或使用原有作者单源快捷方式
- **THEN** 详情不再出现新增跨平台按钮，原有单源行为正常；新平台名称树可在未声明作者转换的普通可搜索来源上工作

### Requirement: 兼容与卸载

新增持久化键缺省/个别条目损坏时 MUST 安全恢复，其他有效条目不受影响。方案 MUST 忽略或清理卸载来源；平台手动名称 MUST 保留不可用来源身份以便恢复。已有收藏、文件夹、系列与排序 MUST 保留。

#### Scenario: 旧数据打开

- **WHEN** 应用打开没有平台名称持久化键的旧数据
- **THEN** 从已知收藏关系展示名称，手动配置为空，旧收藏/方案/快捷方式保持原行为

### Requirement: UI 语言与契约

新文案 MUST 经 `.tl` 提供，并在 assets/translation.json 同时提供 zh_CN/zh_TW。UI MUST 遵循 design-spec 的 token、断点、surface 和 1px 分隔线规则。

#### Scenario: 双语与布局

- **WHEN** 用户以简体或繁体中文打开平台名称树和管理表单
- **THEN** 标题、操作、空状态、来源不可用及错误反馈均来自对应翻译，布局无新增壳层/主题例外
