# Spec Delta

## Purpose

搜索方案保存可复用的跨来源检索组合；作者搜索把标准作者标签转换为各来源明确支持的查询。

## ADDED Requirements

### Requirement: 搜索方案持久化

系统 MUST 支持命名搜索方案，方案至少包含来源顺序、启用状态和各来源搜索选项。名称 MUST trim 后非空、≤30 字符且同库不重名；缺省无方案时 MUST 保持现有全局来源搜索行为。

#### Scenario: 保存检索方案

- **WHEN** 用户保存「补全作品」方案，启用来源 A、B 并为 B 设置非默认选项
- **THEN** 方案保留来源顺序、启用状态和 B 的选项，未选择方案时现有全局搜索行为不变

### Requirement: 方案 CRUD 与恢复

用户 MUST 能新建、重命名、更新、删除和选择方案。读取方案时 MUST 按当前来源 option schema 校验值，未知来源或无效值 MUST 忽略或回退默认值，不得阻塞其他来源搜索。

#### Scenario: 来源选项变更

- **WHEN** 来源 B 删除了方案中已保存的某个选项值
- **THEN** 加载方案时 B 回退该选项默认值，来源 A 仍按方案值执行

### Requirement: 聚合结果一致性

按方案启动聚合搜索时，系统 MUST 按保存顺序加载启用来源，并将该来源的有效选项传递给分页结果页；后续分页 MUST 使用同一组选项，不能退回来源默认值。

#### Scenario: 聚合分页

- **WHEN** 用户选择方案并加载来源 B 的下一页
- **THEN** 下一页沿用方案为 B 解析出的有效选项，而不是重新读取 B 的默认选项

### Requirement: 作者查询能力

来源 MUST 明确声明是否支持作者查询及其转换方式。作者跨源搜索 MUST 仅向支持转换的来源发起请求；不支持来源 MUST 显示可理解的跳过状态。系统 MUST NOT 假设统一 `author:` 语法适用于所有来源。

#### Scenario: 作者能力筛选

- **WHEN** 用户从作者标签发起跨源搜索，来源 A 支持作者转换而来源 B 不支持
- **THEN** 请求只发送给 A，结果页明确显示 B 被跳过及原因

### Requirement: 兼容与卸载

新增持久化键缺省时 MUST 使用现有搜索设置；来源卸载或配置删除后，方案 MUST 忽略或清理该来源条目而不影响其他来源。现有单源搜索、历史和快捷方式行为 MUST 保持。

#### Scenario: 来源卸载

- **WHEN** 用户卸载方案中的来源 B
- **THEN** 方案仍可打开并执行其他来源，B 的条目被忽略或清理，单源搜索历史和快捷方式不变

### Requirement: UI 语言与契约

所有新用户可见文案 MUST 通过 `.tl` 提供，并在 `assets/translation.json` 同时提供 `zh_CN` 与 `zh_TW`。方案与作者结果 UI MUST 遵循 `design-spec.md` 的 token、断点、浅色 surface 和 1px 分隔线规则。

#### Scenario: 翻译与视觉契约

- **WHEN** 用户打开方案管理或作者搜索结果状态
- **THEN** 新文案来自 `.tl` 双语词条，布局使用现有 token、断点和浅色 surface
