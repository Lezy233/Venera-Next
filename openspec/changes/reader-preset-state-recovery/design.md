# Design

## D1 证据与边界

正式约束为 openspec/specs/reader/mode-presets/spec.md 和 settings/reader-scope-model/spec.md。旧归档reader-mode-presets设计D4曾定义下拉仅为局部上次提示，本change以owner B3决定替代该提示语义；保留正式契约的19键、缺失键不改值、作用域正交及删除不回写。

入口：lib/features/settings/reader_presets.dart 的 ReaderPresetSelector局部_appliedId/build/_apply，以及管理页apply；lib/foundation/reader_presets.dart 的_snapshot/apply；settings/reader.dart与reader/quick_settings_panel.dart分别传当前作用域与漫画作用域。先跑真实页面销毁/重建失败用例，不把局部变量缺少恢复等同于参数未保存。需要的实现诊断由executor完成，architect仅规划与复核。

## D2 持久引用与身份

新增向后兼容的settings元数据readerPresetSelections（或等价封装），记录最后成功应用的presetId。身份明确区分global、device+已有deviceId、comic+(sourceKey,comicId)，漫画元组须无分隔符歧义；两个来源相同comicId不得串用。缺省/坏记录/失效ID均为无，不更改既有参数，也不推断旧数据已选择某方案。同值不同ID方案保持用户明确选择的身份。

方案参数和目标引用通过同一appdata.updateSettings事务写入最新草稿。读取/清除引用不得启用设备或漫画层；选择「无」只清当前层引用，不清参数，不影响其他层。active调用先按现有规则归一到具体作用域，UI继续传明确层。异步操作捕获原作用域、deviceId/漫画身份及数据目录归属，页面/身份切换不能回写到新归属或显示旧操作成功。缺失方案不得造成成功应用提示。

## D3 匹配与生命周期

引用不是设置的第二数据源。只在目标ID存在、具有至少一个有效白名单键且其声明键均匹配时显示该名称。逐键用当前作用域ReaderPreferenceStore的规范化生效值比较；部分方案只比较声明键，数值表示int/double按既有normalize语义处理。readerMode比较该层现有求值结果（global不掺device/comic；device沿用启用/继承；comic沿用readerModeOverride与布局resolve）。autoReaderMode读取实际作用域值，不直接用_snapshot进行匹配，因为_snapshot强制auto=false会掩盖手改。保留既有模式应用与求值通道，不借此重构auto/override机制。

手改组合键后立即重算，失配显示无；手改方案外亮度等不改变匹配。匹配恢复时可重新显示原引用；不自动改参数。切换层/漫画、重进、重启均从同一存储读取。管理页应用同样保存引用；重命名按ID显示新名称；删除使引用无效但不回写参数；方案更新后按新值重新校验。重置目标层应清其选择引用，不能因重置值偶然相同继续声称已选择；其他层引用保留。

## D4 保存可信度

### D4.1 成功边界与操作范围

本次apply写入的appdata.json及按当前同步排除配置需要生成的syncdata.json全部成功，才算保存成功，才可显示已保存并派发当前页成功效果。syncdata.json不是可忽略的失败；不得吞掉其异常当作成功。沿用现有writer，B3可增加局部/显式opt-in恢复能力，但不得改变其他设置调用默认的失败语义或全局回滚任意draft。

恢复对象是在串行writer实际准入时捕获的本操作字段及存在性：目标层被本次apply改动的组合键、漫画模式override、启用状态和目标选择引用；若本操作首次创建设备身份，相关身份也须在仍归本操作拥有时恢复。全局其他键、其他设备/漫画、方案库、历史等无关数据不属于回滚对象。None/目标重置的本change选择状态变更适用同一失败原则。

### D4.2 首次保存失败：回滚，不保留失败参数作为已应用

不论是appdata.json.tmp写入失败还是部分文件成功，操作都失败。必须恢复本操作仍拥有的内存参数和引用到准入前状态；不能仅清新引用却保留失败apply发布的组合值，也不能仅隐藏toast。恢复前后的通知不得发出新方案成功应用效果。

恢复须在相同原数据目录、同一序列化写入体系中进行，按字段/目标身份校验所有权。若后续合法操作已覆盖同字段/同目标，不得把它退回旧快照；保留后续值，并将其视为已接管的最新状态。禁止整份appdata快照回滚或无条件替换整个device/comic容器覆盖其他更新。若目录已切换，禁止向新目录执行旧恢复；旧目录恢复通过原准入归属完成或明确留作未完成，不能解除隔离后写新目录。

恢复内存后作一次有界补偿持久化：从最新有效内存草稿重新生成完整appdata.json和当前规则要求的syncdata.json；即使appdata.json已成功也必须补偿写回，并以两文件全部写回成功作为耐久恢复完成。syncdata内容必须重新按当前排除配置投影，不能把旧appdata原文复制给syncdata。补偿只写本次准入原目录，不发新的同步请求；已成功的原文件不因首个异常而被遗漏。

### D4.3 补偿结果、提示与重试

| 状态 | 参数/引用与磁盘 | UI及下一步 |
|---|---|---|
| 首次保存全部成功 | 本次新值和引用均耐久保存 | 正常已保存，归属有效才派发成功效果 |
| 首次失败、补偿全部成功 | 本操作旧值/引用恢复，保留后续合法更新；所有要求文件已写最新恢复草稿 | 仍报告本次保存失败，不显示已保存；允许用户重新应用，按最新草稿发起新操作 |
| 首次失败、补偿仍失败 | 内存按D4.2恢复，但磁盘可能混合新旧，不宣称已耐久回滚 | 显示本地化持续错误“保存失败，恢复未完成”，提供明确重试恢复；同目标新apply/清引用/重置暂停，其他目标不被全局锁死 |

恢复未完成状态必须由目标级操作管理承载，不能只存在已销毁的selector里；同进程重进页面仍显示错误，当前方案显示无/未确认（而非新方案已应用）。保留初次与补偿两次错误用于诊断，不无限后台重试。

“重试恢复”仅重试把最新的恢复后有效状态写入原目录全部要求文件，不自动再次应用曾失败的方案。全部写回成功后解除该目标暂停，重新显示校验后的旧有效引用；用户随后明确选择方案才重新apply。反复恢复失败仍保持错误和暂停，不出现已保存。归属已失效时不跨目录/身份重试，报告原目标恢复未完成。

### D4.4 故障退出的边界

本change不引入多文件ACID或跨进程恢复日志，不承诺文件持续不可写或补偿未完成时强制退出后仍可耐久回滚。不能把进程内恢复状态当作已经落盘的承诺。故障未恢复即重启时，按实际appdata.json加载并按D3校验现存引用/参数；可能读到旧或已部分提交的新值，不自动重放失败apply，也不补发历史已保存提示。若有可证明的不一致或无效引用，显示无/既有错误。此边界只适用于已经明确报告恢复未完成后的故障退出；正常成功/补偿成功后的重启必须分别保持新值/恢复后的旧值。

### D4.5 必测失败矩阵

1. 真实阻断appdata.json.tmp：首次失败后内存恢复、补偿成功后磁盘旧参数/旧引用恢复，原故障不再假成功。
2. appdata.json成功而syncdata.json失败（及反向单文件失败）：对已成功文件也补偿；补偿完成后两文件投影一致，重载得到旧值/引用。
3. 首次与补偿均失败：持续错误、同进程重进仍未确认、目标暂停；解除故障后重试恢复只恢复旧状态，明确再次apply才保存新方案。
4. 恢复排队前发生其他键/其他目标更新及同字段后续接管：补偿保留它们；切数据目录不能写新库。测试不能仅mock抛异常，要至少保留真实文件故障覆盖。
