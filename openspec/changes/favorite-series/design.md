# Design

## 现状与边界

`FavoritesRepository` 使用动态文件夹表；收藏身份是 `(id, ComicType)`。系列必须使用固定表，避免把系列名当作 SQL 表名。`FavoritesManager` 的事务与通知机制作为唯一写入入口。收藏页当前以文件夹名区分位置，系列入口应引入明确的选择类型，不把系列名编码进文件夹哨兵值。

## 数据模型

新增固定表 `favorite_series`（`id TEXT PRIMARY KEY`, `name TEXT NOT NULL`, `display_order INTEGER NOT NULL`）和 `favorite_series_items`（`series_id TEXT`, `comic_id TEXT`, `comic_type INTEGER`, 联合主键，外键指向系列）。成员指向收藏身份而非某个文件夹记录；同一作品可位于多个文件夹和多个系列。删除最后一份收藏时清理孤儿成员；删除文件夹不删除仍被收藏的系列成员。

系列 CRUD、排序和成员变更全部经 repository transaction 执行，并由 manager 发布一次变更通知。数据库升级必须保持旧库可读；整体 `local_favorite.db` 同步自然携带固定表。旧版 Pica 导入不推断系列。

## UI

收藏侧栏新增「系列」分组及系列行，复用现有列表/详情布局、token、断点和 1px 分隔线。系列内容页使用现有卡片/列表组件，但显示所有系列成员，不按 All 视图去重。现有移动/复制到文件夹操作不自动加入系列；多选操作另提供「加入系列」「移出系列」。

系列管理支持新建、重命名、排序、删除；删除系列只删除映射，不删除收藏。名称 trim 后非空、同层不重名，沿用现有文件夹命名校验规则。当前选中系列持久化使用独立键，旧文件夹选择值继续兼容。

## 框架容纳检查

- token、断点、surface、列表/详情容器均可复用 `design-spec.md` 第 2–4、7.3 节，无新增例外。
- 新文案遵循第 6 节，统一经 `.tl` 并补 `zh_CN`/`zh_TW`。
- 不引入深色阅读器例外、第二套窗口框架或卡片套卡片。

## 验证与风险

覆盖 schema 升级、系列 CRUD/排序、成员幂等、孤儿清理、事务回滚、管理器通知、旧库兼容和收藏页选择持久化。重点风险是动态文件夹表与系列固定表的查询边界，以及 All 去重结果不能误用于系列视图。
