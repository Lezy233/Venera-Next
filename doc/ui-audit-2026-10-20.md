# Venera-Next UI/UX 审计报告（PC 适配 · 设置区 + 桌面外壳）

日期：2026-10-20　范围：`lib/features/settings/`、`lib/app_shell/`、`lib/components/`（navigation_bar / window_frame）

## Context

- Surface：Flutter 桌面应用（Windows / macOS / Linux），设置页（list-detail 双栏）+ 桌面外壳（自定义标题栏 + 侧栏导航）
- 主要用户任务：找设置、改设置；阅读漫画；管理收藏
- 主要 CTA：设置分类选择、顶栏搜索框、侧栏导航
- 假设：目标用户是从移动端迁移过来的 PC 用户，预期效率型工具（用户已声明倾向 VSCode 风格）

## 诊断标签说明

- 执行鸿沟：用户找不到怎么做（入口 / 信息架构 / 选择过多）
- 评估鸿沟：用户看不出发生了什么（状态 / 反馈）
- 失误（slip）：目标对、操作错；错误（mistake）：心智模型本身就错了

---

## Findings

### P0（阻断级）

**1. Reading 设置页是无分组的 ~30 项平铺列表，且同一套界面被三处复用**

- 证据：`reader.dart` 889 行，缩略图 4–5 个 Select、阅读模式、亮度、翻页手势、页面动画、E-Ink 三连 slider、自动翻页、自动滚动三连 slider、鼠标滚轮、长按缩放、状态栏、快速收藏、图片预处理（内嵌 JS 代码编辑器）、预加载数、页码、章节评论……全程只有 `Divider`，没有任何分组标题。整个 settings 目录 26 个文件里 `SettingPartTitle` 只被用了 2 次（都在 app.dart）。同一个 `ReaderSettings` 组件又被 `settings_panel.dart` 在**阅读器内**整页复用（带 comicId）。
- 诊断：执行鸿沟 + 认知超载（Hick's Law：选项无分组时决策时间随数量线性恶化）
- 为什么痛：这是用户抱怨"设置绕来绕去"的核心。用户想找"翻页动画"，要在 30 个无标题条目里扫视；E-Ink 三连 slider 无条件可见（虽然包在 AnimatedVisibility 里，但平铺依旧挤占扫描路径）；图片预处理这种 1% 用户用的功能排在常用项中间。
- 修复：
  1. 给 Reading 页引入分组标题（组件已有：`SettingPartTitle`），建议分 6 组：阅读模式 / 翻页与手势 / 显示与亮度 / 缩略图导航 / 自动阅读 / 高级（E-Ink、图片预处理、JS）。
  2. 低频项（E-Ink、自定义图片处理、预加载数）收进"高级"折叠区或二级页，默认折叠。
  3. 阅读器内的面板另做一个**精简版**（模式/亮度/方向 5–6 项），不复用整页设置。
- 验收：盲测——让用户找"自动翻页间隔"，3 秒内定位到组。

**2. 三套 WebDAV 配置互相独立，标签区分不了**

- 证据：`app.dart` 的 App → Data 分类里平级摆着三个入口："Data Sync"（`_WebdavSetting`）、“Comic Archive Backup”（`BackupWebdavSetting`）、“WebDAV Comic Library”（`WebDavComicLibrarySetting`），三个各自弹窗、各自填 URL/用户名/密码。
- 诊断：执行鸿沟 + 错误（mental model：三个名字都含 WebDAV，用户无法建立"它们是两件事——同步设置数据 vs 备份漫画 vs 在线看漫画"的模型）
- 为什么痛：用户配置一遍 WebDAV 以为万事大吉，结果发现收藏备份没生效——评估鸿沟 + 重复劳动。
- 修复：
  1. 三个入口合并为一个"远程存储 / WebDAV"配置页：一份连接配置（复用 `WebDavConnectionFields`），下方用 Tab 或分组说明三种用途各自开关。
  2. 若暂不合数据模型，至少在 UI 上让一个"连接"主配置 + 各用途复用，并在备份入口显示当前连接状态（已配置/未配置）。
- 验收：配置一次连接后，三个功能都能直接用。
- 状态（2026-10-20，`settings-ia-cleanup`）：已实现。App → Data 收敛为单一“远程存储”入口；共享连接 key `webdav.connection` + 三用途开关/状态/说明；旧配置启动迁移并保留旧 key，不一致时以数据同步为准并提示确认。

### P1（重要）

**3. 设置首页右侧默认空白，双栏优势没发挥**

- 证据：`settings_page.dart` 的 `buildRight()` 在 `currentPage == -1` 时返回 `SizedBox()`；所有入口（侧栏设置按钮、Ctrl/Cmd+,）都只 `to(() => const SettingsPage())`，无人传 `initialPage`。
- 诊断：执行鸿沟（到达设置页后没有默认着陆内容，用户面对一半空屏）
- 修复：双栏模式下默认选中第一个分类（Appearance 或按使用频率）；同时把 `initialPage` 接起来——顶栏菜单的 Settings… 可直达常用项。这是低成本高收益。
- 验收：打开设置页即有内容。

**4. 分类归属混乱：行为偏好散落在错误的地方**

- 证据：`explore_settings.dart` 里放着"Reverse default chapter order"（`AppPreferences`）和"Initial Page"（启动页，App 级行为）；"Reading statistics" 是一个完整统计页，却占着设置分类的一个格子；Debug（JS 控制台）对普通用户无条件可见。
- 诊断：执行鸿沟（IA 与用户心智模型不符：用户找"启动时打开哪个页面"不会去"浏览"分类找）
- 修复：
  1. "Initial Page"、章节排序这类 App 级行为归入 APP 分类。
  2. Reading statistics 移出设置，放到历史/统计页里，或作为 About 的子入口。
  3. Debug 折叠进 About → 高级，或加开关（连续点版本号 7 次之类）再显示。
- 验收：把 9 个分类名给用户看，让用户猜每个分类里有什么，命中率明显提升。
- 状态（2026-10-20，`settings-ia-cleanup`）：已实现。Initial Page / Reverse default chapter order 迁入 APP → Behavior；设置主导航 9 → 7（移除 Reading statistics / Debug）；Debug 与 Logs 收进 About → Advanced；统计入口保留在历史页顶部工具区。

**5. 阅读设置三层作用域（全局/设备/单部漫画）暴露在同一平面**

- 证据：`reader.dart` 顶部同时有 "Enable device specific settings" 和单部漫画的 "Customize other settings for this comic"，每项 setting 还传 `useDeviceSettings`/`comicId`；`_scopeTile` 的副标题写着 "Change default preferences in Settings → Reader"——用户此刻就在设置里，这句话指向不明确。
- 诊断：执行鸿沟 + 错误（作用域心智模型过于复杂，slip 风险：改了"这部漫画"以为改了全局）
- 修复：
  1. 全局设置页只显示全局项；设备/单部漫画的作用域切换改成明确的 segmented 选择（默认 / 此设备 / 此漫画），选中后整页内容随作用域变化，而不是每个 item 各自处理。
  2. 副标题改为具体动作："这些设置只对本漫画生效。修改默认设置请前往 设置 → 阅读"。
- 验收：用户在阅读器内改一项设置后，能明确说出"这项改动作用在哪一层"。
- 状态（2026-10-20，`settings-ia-cleanup`）：已实现。阅读设置顶部改为 默认 / 此设备 / 此漫画 SegmentedButton，整页按作用域重建；阅读器面板默认“此漫画”，删除 `_scopeTile`；每层保留一键重置与持续的作用域说明。

**6. 顶栏搜索框行为随页面变化但外观零提示**

- 证据：`desktop_top_bar.dart` 的 `DesktopSearchBox` 恒显示提示词"Search"；但 `desktop_chrome.dart` 里同一控件在收藏页是本地过滤、在阅读器内按提交会打开章节列表（`submitSearch` → reader.openChapters）、其他页才打开全局搜索。Ctrl/Cmd+F 同理。窗口 <900px 时搜索框整个消失。
- 诊断：评估鸿沟 + 错误（同一 affordance 三种行为， conceptual model 断裂："我在搜什么？"）
- 为什么痛：这是 VSCode 风格里 command center 的位置，用户预期它是最强入口，结果行为漂移。
- 修复：提示词按上下文变化（"搜索收藏…" / "搜索章节…" / "全局搜索…"），或在框内右侧加当前目标的小标识；阅读器内建议改成真正的章节过滤而不是"跳转到章节列表"。
- 验收：用户在三个页面分别聚焦搜索框，不看文档就能说出这次搜索作用于什么。

### P2（打磨）

- 断点不一致：设置双栏阈值 `720`（settings_page）vs 导航栏 `600/1300`（consts.dart）vs 搜索框 `900`（desktop_top_bar）。建议收敛到一套断点常量。
- 宽屏下 `PopupWindowSetting`（代理 / DNS / WebDAV / 关键词屏蔽）仍用居中弹窗，而不是在双栏右侧内容区就地展开——与 VSCode"设置就地编辑"的心智不符。
- 侧栏开关按钮只在收藏页可用（`favoritesActive` 判断），其他页面按钮消失且无解释，可禁用态替代隐藏。
- 设置分类左侧选中的 `arrow_right` 图标是移动端语言，PC 上多余。
